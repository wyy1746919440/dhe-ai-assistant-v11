四统一设计原则与待确认项裁决（原 7 项已全部定稿）

项口径
统一字段商品名称 · 价格 · 库存 是基础项；商品ID 按场景取舍——上架 / 下架卡不显示（商品还没上架，ID 对运营商无意义），补货卡也不显示（改看箱规），改价 / 订单明细卡保留（放名称下方副行，等宽灰字，与现有 .ln 一致）。
补货卡字段补货单卡不显示价格与商品ID，核心只讲三件事：缺货数 / 缺货箱数 / 补货量；箱规（N 件/箱）放名称下方副行，缺货箱数＝缺货数 ÷ 箱规、按「N 箱 M 件」展示。口径与现有系统「库存查询 → 生成补货单」页一致（价格不参与补货）。
库存列取舍按「这个场景有没有库存可言」判断：上架＝没有（不显示）；下架＝显示现有库存（还要标「将清空 N 件」）；改价＝显示现存；补货＝显示缺货数 / 缺货箱数（补货员关心的是缺口，不是存量）。
价格可编辑上架卡价格默认取商品库自身价，但必须可改；改动行加 input.chg 蓝框，diff 区单独列「价格改动 N 项（改前 → 改后）」。
状态文案状态列一律用文字不用符号：成功 / 失败，禁止 ✕ ✓；失败原因放名称下方副行红色 .ln.reason，机器级与商品级分开标「对象」。
补货量口径2026-10-16 定：不用算法建议量，补货量＝最大库存（后台「补满」配置值）− 现存，缺货数同口径；补货量可逐项手改。不再有模式切换（原「按销量 / 按补满库存」.seg 二选一取消，「静态柜固定按销量」的约束一并移除）。
卡片宽度由原 262px 调整为 300px（375 屏内可用宽约 308px）；若实际渲染仍挤，商品ID 缩为副行 + 价格/库存合并成「¥3.00 · 12」。
两段式写卡预览（可编辑表格 + 改动 diff）→ 点击确认才调用写接口；只对改动过的行签发 confirm_id；取消则什么都不发生。沿用 cardPriceTable / cardStockTable 逻辑。
校验与失败AI 侧不重写校验：适用机型、建模、价格区间、库存上下限全部由后端判定，卡片只负责标红 + 原样透传原因。
多台执行统一为 ca-api 单机循环；结果卡必须逐台列出成功/失败与原因（W6），不得整批报失败、也不得静默跳过。
下架处理按机型分两套：智能柜＝移除该商品、库存清零；售货机＝把该货道换成默认商品（不清空，货道继续售卖）。
上架位置按机型分两套：售货机＝货道，逐个指定（默认分配空闲货道、可点选改，副行给最大库存与现存）；智能柜＝层（无货道概念）。
批量上架不逐台指定，按各机自动分配；需精确指定走单台卡。
读卡操作位读卡不带「确认执行」按钮；只在确有明确下一步、且是该条数据的自然延续时才给按钮（如补货记录 → 生成补货单）。卡内已有信息不做循环跳转（离线原因卡不再给「查硬件状态」），跨能力动作不硬凑（需要重启直接问即可）；没有下一步就不给按钮区。
结果卡闭环结果卡（W6）不能只报失败——成功 / 失败两个动作都要有下文：失败项可重试，成功项可展开明细（W6-b），两者同源同批，成功台数 + 失败台数 = 命中总数。
明细卡是只读卡，不带「确认执行」；完整清单在卡内滚动展示。
说明行（exec-note）卡片底部灰色说明行只承载本条数据的口径——能查多久、数据来源、默认给什么（如「最多可查近 180 天」「默认给合计」）。不写「你可以接着问我…」这类引导话术：用户想追问直接打字就行，卡片不需要教他怎么说。
移动端不做导出一律不提供「导出 / 下载」——这是移动端，不是 PC 端；卡片内的列表直接在卡内滚动看全量，不生成文件。需要留存的场景（对账、存档）引导到 PC 端管理后台。
多选与全选凡是逐行勾选的表格 / 列表，列头（表格）或列表顶部（弹层）必须给「全选」控件，不允许只能逐行点。三态：表格用方框 ☑ 全选 / ▣ 半选 / ☐ 未选；弹层用圆形 ◉ / ◍ / ○（与行内圆勾选一致）。品牌色描边。
选中数实时回显到 diff 区标题与按钮文案（如「为这 2 台生成补货单」）；弹层回显在右上角计数。
默认态按场景给：补货记录默认勾中 7 天以上未补货的，下架默认全选。
